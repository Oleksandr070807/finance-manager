# Вимоги до проєкту FinanceManager

## 1. Призначення
Веб-застосунок для особистого фінансового обліку, що дозволяє відстежувати загальний баланс, керувати банківськими рахунками та готівкою, аналізувати місячний бюджет за категоріями та вести історію транзакцій.

## 2. Ролі користувача
- Користувач — перегляд загального балансу, додавання та фільтрація транзакцій, управління рахунками, категоріями та місячним бюджетом.
- Адміністратор — управління користувачами та загальними налаштуваннями системи.

## 3. Сутності предметної області
| Сутність    | Атрибути                                                 |
| ----------- | -------------------------------------------------------- |
| Account     | id, title, type (checking/cash/card), balance, acc_num   |
| Category    | id, name, type (income/expense), icon, color             |
| Transaction | id, account_id, category_id, title, amount, date, type   |
| Budget      | id, category_id, limit_amount, spent_amount, month, year |

## 4. Зв'язки
Account 1 — ∞ Transaction; Category 1 — ∞ Transaction; Category 1 — 1 Budget

## 5. Сторінки
1. `/` — головна: картка загального балансу (доходи/витрати/темп заощадження), швидкі блоки «Рахунки», «Місячний бюджет» та «Нещодавні транзакції».
2. `/accounts` — рахунки: огляд усіх платіжних карток, готівки та банківських рахунків.
3. `/transactions` — транзакції: повний список операцій із можливістю пошуку за описом, фільтрацією (за категорією, періодом, рахунком) та пагінацією.
4. `/categories` — категорії: налаштування категорій доходів і витрат.
5. `/budgets` — бюджети: управління місячними лімітами та відстеження прогресу витрат.

## 6. Функціональні вимоги
F1. Динамічне завантаження списку транзакцій та відображення статусу пагінації (наприклад, 1–6 із 128).
F2. Пошук транзакцій за описом та фільтрація за категоріями, періодом чи рахунком без перезавантаження сторінки.
F3. Додавання нових транзакцій через модальне вікно («Додати транзакцію») з валідацією суми, дати, рахунку та категорії.
F4. Інтерактивні прогрес-бари для відстеження використання місячного бюджету по кожній категорії.

## 7. Нефункціональні вимоги
N1. Повна адаптивність інтерфейсу від 360 px (підтримка мобільних пристроїв з адаптивним гамбургер-меню).
N2. Lighthouse Performance ≥ 85.
